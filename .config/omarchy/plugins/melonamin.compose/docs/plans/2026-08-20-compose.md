# Plan: Compose for Omarchy

Build Compose as a standalone Omarchy shell plugin that makes XCompose approachable without replacing it. The plugin provides one adaptive overlay: a compact Quick picker for finding and inserting effective Compose results, and an expanded Studio for safely browsing and editing `~/.XCompose`. It follows the root-level structure and source-only installation model of `omarchy-flare`, uses the plugin ID `melonamin.compose`, registers its own `Super + Ctrl + ;` shortcut at runtime, and requires no upstream Omarchy changes.

The native XCompose file remains the only source of truth. Local rules are edited directly with lossless source-span patches; recursively included Omarchy, locale, system, and user files are searchable but read-only, with an Override action that writes a later local rule. The plugin does not become a global keystroke monitor and does not add accounts, synchronization, dynamic forms, scripts, rich text, usage analytics, or a second expansion engine.

Keep the repository flat where a file is a primary plugin entry point or shared model, and use subdirectories only for reusable visual components, the runtime Hyprland helper, scripts, fixtures, and tests. Runtime code may rely on Bash, coreutils, `hyprctl`, `omarchy-shell`, `wl-copy`, `wtype`, `systemctl`, and the supervised Omarchy `fcitx5` service; Node is a test-only dependency.

## Validation Commands

- `tests/static.sh`
- `node --test tests/*.test.js`
- `tests/transaction.test.sh`
- `tests/integration.sh`

The first three commands are headless and must pass from the repository checkout. `tests/integration.sh` requires a running Omarchy shell and Hyprland session, temporarily exercises the real user Compose file, restores it with a trap, and must be run only after the headless commands pass.

### Task 1: Establish the repository and plugin lifecycle

Create a minimal but genuinely loadable standalone plugin before implementing document behavior. The service owns persistent shared state and the runtime shortcut, while the overlay proves that Quick and Studio can be summoned through the standard shell lifecycle. Model the manifest, installation story, runtime path discovery, tests, and documentation layout after `omarchy-flare` without copying Flare-specific bar or pointer behavior.

- [ ] Add an MIT `LICENSE`, a concise initial `README.md`, and a `manifest.json` for version `0.1.0` with ID `melonamin.compose`, display name `Compose`, author `melonamin`, homepage `https://github.com/melonamin/omarchy-compose`, kinds `service` and `overlay`, `keepLoaded: true`, and entry points `Service.qml` and `Compose.qml`.
- [ ] Add `Service.qml` with the shell-injected `shell` and `manifest` properties, derive the repository path only from `manifest.__sourceDir`, and expose shared plugin state to `Compose.qml` through the shell's matching service injection.
- [ ] Add placeholder `Compose.qml` lifecycle methods `open(payloadJson)` and `close()` that support `{"mode":"quick"}` and `{"mode":"studio"}`, capture keyboard focus, dismiss cleanly, and use the `melonamin-compose` layer-shell namespace.
- [ ] Add an IPC target named `compose` with `quick`, `manage`, `close`, and `status` methods so `omarchy-shell compose quick` is the documented fallback when a shortcut is disabled or unavailable.
- [ ] Store the configurable shortcut inline on this plugin's `plugins[]` entry in `~/.config/omarchy/shell.json`, default it to `SUPER + CTRL + SEMICOLON`, and treat an empty value as disabled without writing defaults merely because the plugin loaded.
- [ ] Add `hypr/compose.lua` and follow Flare's runtime registration pattern: load it through `hyprctl eval`, register the shortcut without editing user Hyprland files, detect collisions, reinstall after Hyprland reloads, and unregister from the already-loaded Lua global when the service is destroyed.
- [ ] Make shortcut installation idempotent and queue a second installation when a compositor reload arrives while the first `hyprctl eval` is still running.
- [ ] Add `tests/static.sh` to validate the manifest contract, expected entry points, Bash syntax, repository paths, and absence of hard-coded checkout locations; add initial model tests for shortcut normalization and mode payload parsing.
- [ ] Document installation with `omarchy plugin add https://github.com/melonamin/omarchy-compose.git --enable`, removal, IPC fallbacks, default shortcut, collision behavior, and the guarantee that the plugin does not edit Hyprland configuration.

### Task 2: Build the lossless XCompose document and effective-library model

Implement parsing as a document model rather than a serializer. Every physical source retains its exact raw text and node spans, allowing the plugin to understand valid rules while preserving comments, blank lines, ordering, line endings, includes, and syntax it does not own. Included sources participate in effective resolution and search but never become writable through Studio.

- [ ] Implement `ComposeModel.js` as plain JavaScript that can be imported by QML and loaded as CommonJS by Node tests.
- [ ] Tokenize a Compose document into blank, comment, include, rule, malformed, and unknown nodes while retaining exact raw text, character spans, line numbers, newline style, and source identity.
- [ ] Parse standard event sequences, optional modifiers, `<Multi_key>`, string-only, keysym-only, and combined string-plus-keysym results, escape sequences, and trailing comments without normalizing untouched text.
- [ ] Decode quoted result strings for previews and insertion; when a valid rule has only a result keysym, derive its UTF-8 result with `xkb_keysym_to_utf8()` semantics, retain keysyms that have no UTF-8 representation as non-insertable rules, and encode edited UTF-8 text back into a single valid Compose rule with correct escaping for quotes, backslashes, tabs, and newlines.
- [ ] Implement `SourceLoader.qml` to read the root file and recursively load includes without invoking a shell through interpolated strings; resolve explicit paths plus `%H`, `%L`, and `%S` according to the XCompose search rules and locale compose map.
- [ ] Detect missing or unreadable includes and include cycles, stop only the affected branch, and return source-specific diagnostics while retaining valid rules from the rest of the graph.
- [ ] Classify sources as Mine for the root `~/.XCompose`, Omarchy for packaged Omarchy Compose data, System for locale/X11 sources, and Included for any other user include.
- [ ] Resolve the effective library in file order using libxkbcommon conflict semantics: when two sequences are equal or either is a prefix of the other, retain the later definition as active and mark the earlier definition shadowed; retain shadowed definitions for diagnostics and source inspection rather than discarding them.
- [ ] Treat an exact sequence collision as an override relationship and a prefix collision as a warning that also shadows the earlier conflicting definition, not as a parse error that invalidates the rest of the source.
- [ ] Provide transformations for replacing or deleting one local rule span and for appending a new rule to a clearly marked local section at the end of the root document.
- [ ] Add fixtures for comments, whitespace, modifiers, string-only, keysym-only, and combined results, keysyms without a UTF-8 representation, escaped results, multiline output, nested includes, all include substitutions, missing files, cycles, duplicate sequences, both prefix orderings, unknown syntax, UTF-8, CRLF, and a missing root file.
- [ ] Prove in `tests/model.test.js` that parsing and emitting without an edit is byte-identical, replacing or deleting one rule changes only its intended span, keysym-only UTF-8 fallback matches libxkbcommon, and exact and prefix conflicts retain only the later definition as active.

### Task 3: Implement transactional file persistence, activation, rollback, and Undo

Keep privileged or destructive behavior out of QML. A small Bash helper receives candidate content over standard input, verifies that the root document has not changed since Studio loaded it, preserves the current file, performs an atomic same-directory replacement of the file or a symlink's final referent without replacing the symlink itself, and activates the result through Omarchy's supervised XCompose service. The helper must never interpret candidate text as shell code or pass it through command arguments.

- [ ] Add `scripts/compose-file` with explicit `revision`, `apply`, and `undo` subcommands; use `#!/bin/bash`, Bash 5 conditionals, quoted paths, `mktemp` in the destination directory, and machine-readable single-line JSON results.
- [ ] Resolve the production target from `XCOMPOSEFILE` when set and otherwise use `$HOME/.XCompose`; provide an explicit file option for isolated tests without allowing an unresolved or empty target.
- [ ] Resolve a symlinked target to its final referent for `revision`, `apply`, and `undo`; reject broken or cyclic links and a link whose resolved target changes after revision, create temporary files beside the referent, and leave the user's symlink chain intact.
- [ ] Make `revision` return a SHA-256 digest plus file-exists, permission, symlink, and resolved-target identity metadata, using a stable sentinel when a non-symlink root file does not yet exist.
- [ ] Make `apply <expected-revision>` reject stale content, metadata, or symlink-target changes before writing, read the complete candidate from standard input, preserve the existing referent's mode, write and sync a temporary file, and atomically rename it over the resolved referent.
- [ ] Store timestamped backups under `${XDG_STATE_HOME:-$HOME/.local/state}/omarchy-compose/backups/`, retain a bounded recent set, and avoid littering the user's home directory with backup files.
- [ ] Activate a successful write with `omarchy restart xcompose`, then verify `omarchy-fcitx5.service` is active through `systemctl --user`.
- [ ] If activation fails, preserve the rejected candidate under the state directory, restore the prior file atomically, retry the restart once, and report whether rollback restored service health.
- [ ] Make `undo` restore the most recent applicable backup through the same revision guard and activation path rather than copying blindly over a newer external edit.
- [ ] Keep parsing and candidate validation in `ComposeModel.js`; the Bash helper is responsible only for revision checks, storage transactions, activation, and recovery.
- [ ] Add `tests/transaction.test.sh` with a temporary HOME, explicit temporary target, stubbed `omarchy` and `systemctl`, and assertions for creation, permission preservation, stale revision rejection, atomic success, symlink-preserving apply and Undo, broken-link and retargeted-link rejection, backup pruning, activation failure, rollback, and rejected-candidate retention.

### Task 4: Build the Quick picker and safe text insertion

Turn the placeholder overlay into the daily-use surface. Quick should open instantly with search focused, make the result and its key sequence legible at a glance, and insert into the previously focused application without monitoring global typing. Search and ranking stay deterministic and local; no usage tracking or online data is introduced.

- [ ] Add search indexing and ranking to `ComposeModel.js` across decoded output, trailing comment, display sequence, raw keysyms, and source name; rank exact matches before prefixes and fuzzy matches, prefer active definitions over shadowed ones, and use active local overrides as the final tie-breaker.
- [ ] Default Quick results to active effective rules, exclude malformed nodes, and allow an explicit filter to reveal shadowed definitions when diagnosing a conflict.
- [ ] Add `components/QuickView.qml`, `RuleRow.qml`, and `KeyChip.qml` using Omarchy `Color.menu`, `Style`, `Border`, and reusable `qs.Ui` controls rather than fixed theme colors or dimensions.
- [ ] Render output as the primary visual element, comments as plain-language labels, sequences as `Compose` followed by key chips, and Mine/Omarchy/System/Included as subdued source badges.
- [ ] Render spaces, tabs, newlines, and otherwise invisible output with visible preview markers while retaining the exact decoded value for insertion.
- [ ] Implement keyboard-first behavior: typing edits the search, arrows move selection, Enter inserts, `Ctrl + Enter` copies without typing, the Manage action expands to Studio, and Escape clears search before closing.
- [ ] Add `scripts/compose-insert`, receive arbitrary UTF-8 text over standard input, use `wl-copy` and `wtype` without exposing content in argv or logs, support insert and copy-only modes, and clean up the foreground clipboard process reliably.
- [ ] Dismiss the overlay before insertion, allow focus to return, and use the terminal-compatible `Shift + Insert` path already proven by Omarchy's universal insertion helpers.
- [ ] Handle empty output, multiline text, long phrases, emoji variation selectors, and clipboard/injection failure with concise visible feedback rather than silent success.
- [ ] Extend Node tests for normalization, search ranking, shadow filtering, invisible previews, and stable ordering; add static checks that runtime insertion uses standard input and no network commands.

### Task 5: Expand Quick into the full Studio editor

Implement Studio as a wider state of the same overlay so query, selection, theme, and keyboard conventions remain continuous. The editor presents friendly fields first and keeps raw XCompose syntax behind an Advanced disclosure. Local rules are mutable; included rules are inspectable and produce explicit local overrides.

- [ ] Add `components/StudioView.qml`, `RuleEditor.qml`, and `DiagnosticsView.qml` with source filters for All, Mine, Omarchy, System, Included, and Conflicts; preserve the current query and selected rule when transitioning between Quick and Studio.
- [ ] Use a library list plus inspector layout: show a large decoded output preview, visual sequence, comment, source path and line, active/shadowed state, and context-appropriate actions.
- [ ] Allow local rules to Edit and Delete, included rules to Override, and shadowed rules to inspect the winning definition; never offer a direct write to an included file.
- [ ] Build the friendly rule form around a permanent Compose chip, a recorder for the keys typed after Compose, an editable output field, and an optional comment/label.
- [ ] Map common Qt key events and modifiers to valid X11 keysyms, allow chips to be removed or reordered, and provide a searchable keysym chooser when a key cannot be recorded directly.
- [ ] Put exact generated syntax, modifier controls, optional result keysym, and raw-rule editing under Advanced; reparse raw edits immediately and synchronize friendly fields only when the raw rule is unambiguous.
- [ ] Validate continuously: malformed syntax, invalid escaping, unknown keysyms, or an empty sequence block Save; included overrides, local shadowing, and unusually long sequences remain warnings, while a prefix warning identifies the earlier definition that the later conflicting rule will shadow.
- [ ] When a new sequence exactly matches a local rule, offer Replace existing rule instead of creating a silent duplicate; when it matches an included rule, label the action Create local override.
- [ ] Implement explicit Save and Cancel, layered Escape behavior, dirty-state protection, delete confirmation, and an Undo action backed by `scripts/compose-file undo`.
- [ ] Apply edits only after a final in-memory parse of the complete candidate, send the expected revision and candidate to the transaction helper, and reload the complete source graph after successful activation.
- [ ] Add model tests for recorder-to-keysym mapping, form/raw synchronization, validation severity, replacement selection, override placement, deletion, output escaping, and complete-candidate validation.

### Task 6: Harden live reload, diagnostics, accessibility, and service behavior

Make the plugin trustworthy when files, includes, the compositor, or the input-method service change underneath it. Valid content should remain useful in degraded states, but the plugin must become read-only whenever it cannot prove that a local source-span edit is safe. Every failure should identify the affected source and the recovery action available to the user.

- [ ] Watch the root Compose file while the overlay is loaded and rescan included sources on open, after a root change, after Save or Undo, and after Omarchy updates or shell reloads.
- [ ] If the root changes while no editor is dirty, refresh automatically and preserve the query where possible; if it changes while dirty, retain the draft in memory, disable Save, and offer Reload or Copy raw draft without overwriting external work.
- [ ] Enter read-only degraded mode for malformed root structure, ambiguous source spans, or an unreadable root file; continue presenting every safely parsed effective rule and offer Open raw file for repair.
- [ ] Surface missing includes, include cycles, malformed lines, shadow chains, shortcut collisions, transaction rejection, activation rollback, and input-method health as distinct diagnostics with source paths and line numbers where available.
- [ ] Add an Open raw file action using Omarchy's configured editor launcher and a Validate action that rescans without writing or restarting anything.
- [ ] Let Studio edit the shortcut setting, show whether the requested binding actually registered, allow an empty shortcut to disable registration, and rebind idempotently after a setting change.
- [ ] Debounce search and source refresh work, cap rendered results while retaining the full index, and verify that the shipped system Compose table does not stall opening or keyboard navigation.
- [ ] Make every action keyboard reachable, keep one visible focus target, provide accessible names for icon-only controls, preserve focus during Quick/Studio transitions, honor font and spacing scaling, and avoid conveying errors or selection by color alone.
- [ ] Expose useful read-only IPC status including current mode, open state, requested and registered shortcut, root revision, source/rule counts, diagnostics count, dirty state, and `fcitx5` health without exposing Compose output content.
- [ ] Extend tests for external-edit conflicts, degraded parsing, diagnostic classification, shortcut disable/rebind/collision states, result caps, and status redaction.

The live test must protect the user's current Compose file, prove that shortcut registration and shell lifecycle work, and exercise real insertion and activation. Documentation should make installation feel as self-contained as Flare while being explicit that Compose directly edits a user-owned file.

- [ ] Complete `tests/static.sh` so it validates JSON, entry points, executable scripts, Bash syntax, required files, source-only runtime assumptions, forbidden hard-coded paths, and the absence of undeclared network or package-install behavior.
- [ ] Complete `tests/integration.sh` with prerequisite checks, a backup-and-restore trap for the real Compose file, shell/Hyprland reachability checks, service status assertions, shortcut registration checks, Quick and Studio summon checks, a temporary local rule, activation verification, insertion into a focused GUI field and terminal, Undo, and final byte-for-byte restoration.
- [ ] Ensure the live test uses `omarchy-shell compose` IPC for deterministic setup and checks the Hyprland binding by its Compose description rather than merely counting unrelated binds.
- [ ] Verify manually that Quick and Studio render correctly in representative light and dark Omarchy themes and at increased font/spacing scale; inspect focus, clipping, contrast, long output, key-chip wrapping, warnings, confirmations, and rollback messaging.
- [ ] Capture a polished `preview.png` from the verified Studio state without exposing personal snippets, email addresses, filesystem paths, or other private Compose output.
- [ ] Finish `README.md` with the tagline “Your shortcuts for everything,” preview, features, installation/removal, Quick and Studio usage, shortcuts, IPC, direct-file safety model, backup/recovery locations, runtime requirements, architecture, tests, and known XCompose/application limitations.
- [ ] State clearly that rules stay in `~/.XCompose`, included files are read-only, backups live under the XDG state directory, no global keystrokes are monitored, no network requests occur, and Node is required only for tests.
- [ ] Document how to disable or change the runtime shortcut, how collision reporting works, how to open the raw file, how to validate, and how to recover a rejected candidate or restore a backup manually.
- [ ] Run every validation command from a clean checkout, install through the documented `omarchy plugin add ... --enable` command, remove and reinstall once, and verify that removal leaves no Hyprland configuration edits or active runtime binding.
- [ ] Tag the completed manifest and documentation consistently as the first release only after all headless tests, live integration checks, and visual verification pass.
